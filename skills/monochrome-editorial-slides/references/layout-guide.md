# 版式层次与文字页选版

本页记录真实中文公司介绍稿（2026-10，17 页阅读型）在本风格中的改版经验：用户提出“视觉要有层次”“内容问题可以修改内容”，改版后的写法已做进共享字段与本主题，新稿直接用字段，不再写页面级 `custom_css`。写 `deck.json` 前先读；字段合同以 [共享布局](../../white-blue-slides/references/shared-layouts.md#editorial_columns自由宽度编辑分栏) 为准。

## 每页 2–3 级层次

| 层级 | 承载 | 本主题表现 |
|---|---|---|
| 一级 | 页标题 | 常规字重，语义处 `\n` 断行；文字页可用 `title_size` 72–80 收窄 |
| 二级 | 引导句、条目名、栏目名 | 条目名与栏目名 36 px 半粗（600）；引导句为正文字号的墨色 |
| 三级 | 条目说明、眉题、注记 | 24 px 灰色；眉题 20 px 灰色加字距 |

细线代替卡片分隔层级：`editorial_columns` 的 groups 条目之间自动加细线；清单栏标题下为粗线、条目间为细线；编号条目顶部为墨色线。一页只用一处反白。

## 字段与适用内容

| 内容 | 写法 |
|---|---|
| 架构层、能力项（3–5 项） | groups 单列带图标，`text` 一行说明；贯穿各层的一项（治理、安全）写 `emphasis: true` 反白 |
| 场景要点、价值点（2–4 项），尤其多页同一系列 | groups `numbered: true`，条目 `title` 为“要点，一句判断”式短句，`text` 一到两行；场景序号与英文名写进标题栏的 `eyebrow`，不放进页标题 |
| 实体、产品、服务等名词清单（每栏 3–6 条） | 多个 text 栏，各有 `heading` 并写 `list: true`，条目一行一词组 |
| 关系、规则等“名称 + 解释” | 同上清单栏，条目写 `名称\n说明`，自动成为加粗名称与灰色说明 |
| 口号、关键词 | 标题栏 `eyebrow`（如“自主 · 编排 · 可信”），不与正文同字号并列 |

## 内容可以改

层次不够通常是内容问题：原文是一整段，就没有第二、三级可排。可以把长段改写成“要点 + 一句说明”，把散句合并为清单、把装不下的拆页；保持原意、数字和口径，不添加原文没有的事实，并在 `notes` 记录来源与合并之处（如“项目实施与年度运维为合并原文两项”）。

## 文字较多时的选版

| 结构 | 现象 | 做法 |
|---|---|---|
| `editorial_columns`、`problem_columns` | 文字承载最稳 | 首选；标题栏 + 2–3 个内容栏 + 可选一张 3:4 竖图 |
| `layout: reading` 复合页 | 摘要与区块标题重叠 | 改用 editorial_columns |
| `half_tb` | 图片被压成小条 | 图文左右分栏 |
| `split` | 文字少时留白过多 | 内容不足时换 editorial_columns |

- 标题独占较窄的栏时，加大该栏 `weight` 或降低 `title_size`；末行不留单个字或标点（如“司。”），在语义处手动断行。
- 能力名、产品名不折行：栏宽不够时减少栏数或缩短名称。
- 长段落不靠缩字塞进栏里；超过约三行就改写或拆页。

## 排版 QA

交付前按共享 [基本排版 QA](../../white-blue-slides/references/layout-qa.md) 逐页看截图。本风格重点看：每页是否有三级层次；同一系列场景页的结构与位置是否一致；标题末行是否留单字；窄标题栏是否逐字折行；内容是否挤在上半页。

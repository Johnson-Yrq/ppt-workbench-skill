# 排版 QA 要点与风格开发验证

普通演示稿交付前由 Agent 做共享 [基本排版 QA](../../white-blue-slides/references/layout-qa.md)：运行 `audit_deck.cjs`，逐页看截图检查布局并修改，再交付；下列本风格要点在看图时一并检查。PPTX／PDF 由用户自行导出，Agent 不自动导出、不做 PowerPoint 实看或播放／编辑回归；用户明确要求时完成所要求的部分。分工见共享 [默认交付与职责](../../white-blue-slides/references/export.md#默认交付与职责)。

## 排版 QA 看图要点

- 每页是否有标题 → 条目名或引导句 → 灰色说明三级层次，细线分隔是否清楚，一页最多一处反白；做法见 [版式层次与文字页选版](layout-guide.md)。
- 大标题末行不留单字或标点，窄标题栏没有逐字折行；同一系列的场景页结构与位置一致。
- 黑底页正文、细线和图表是否有足够对比；照片主体与裁切是否完整，满版照片上的标题是否清楚。
- 内容是否挤在上半页、下半页大片空白；长段落超过约三行时改写或拆页。

## 风格开发的样稿阶段

核对八类页面的中文断行、字阶、黑白对比、细线、胶囊、非对称留白、照片裁切、圆形叠放和示例标识。每页文字不得相互覆盖或越出画布。图表须有单位与来源，示例数据不可当作实际成效。

检查翻页、总览、讲稿、全屏、文字编辑、保存重开与离线图片。修改图表数值后重新渲染，保存重开仍保留数据。照片逐张查看：主体与本页内容对应，横幅、圆形与满版裁切后主体完整，满版照片上的标题对比充足，无伪文字、Logo 与手部畸形，整稿调色一致。仅当工具改动涉及 PPTX 导出能力时做相应开发验证。

本包代表性样稿已获用户确认，正式清单为 ready；普通制作与同方向维护不重复索取设计批准。将来另开独立方向时，才先提供新样稿供用户确认，开发自检不能代替该批准。

## 正式共享接入的维护

本包已使用共享构建器和正式 deck 数据；历史独立样稿只作视觉转译记录。维护代码或主题时按共享 [接入规范](../../white-blue-slides/references/adding-styles.md) 检查本次受影响的无图页面、页面 surface、独立页头和共享布局，保留其他风格的外观与功能。speech 与 reading 验证信息密度；只有改动可选 reading 布局时才覆盖其分区。新增通用布局进入共享层，不重建本包专用渲染器。

按改动范围运行清单发现、计划、供图清单与相关代码测试；视觉改动才查看受影响的页面，编辑或导出改动才验证对应功能。仅改说明文档不启动成稿 QA 或导出。安装后确认清单可发现，旧风格不能因本包接入而变为无图或黑底。

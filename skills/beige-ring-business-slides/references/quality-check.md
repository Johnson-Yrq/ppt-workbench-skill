# 检查参考与开发验证

普通演示稿完成内容、必需素材与可编辑离线 HTML 后交付，由用户自行导出和检查。Agent 不默认执行整稿内容审查、批量截图、逐页验收或导出检查；用户明确要求 PPTX、PDF 或代查时，完成相应产物与必要检查。构建失败、结构错误与缺失资源仍须修复，见 [默认交付与职责](../../white-blue-slides/references/export.md#默认交付与职责)。

## 用户自行查看时可参考

- 米白纸面、黑色轻量标题与细线是否统一，中文换行和留白是否自然。
- 圆环是否服务信息组织，细线、箭头和数据图是否区分装饰与真实关系。
- 独立照片是否保持自然色彩；圆形裁切是否保留完整头部，成员姓名与角色是否来自真实资料。
- 表格、图表、KPI 和来源是否可编辑；图表单位、数值与口径是否明确。
- 阅读稿是否具有独立理解所需的上下文；虚构样例是否清楚，数据是否有来源。

## 风格开发与接入

本节用于主题和共享代码开发，不是每份成稿的自动验收流程。用户已于 **2026-10-05** 对「采用这版，并正式安装吗？」明确回复「采用」，批准当前中文样稿方向、正式接入与安装；本包为 **ready / 1.0.0**。历史草稿阶段不限制正常制作，同方向维护不重复索取批准。将来另开独立方向时，才按 [新方向批准规则](../../white-blue-slides/references/adding-styles.md#最小清单示例) 提供代表样稿并确认。

1. 用 `style_packs.py --list` 检查资源、清单与唯一 ID，本方向应出现在正式可用清单中；开发其他草案时可用 `--include-drafts`，不以演示稿 `--draft` 绕过风格状态。
2. 查看受影响的十类代表页面，检查独立页头、中文字号、圆环、头像、照片裁切、灰阶饼图和纯表格。开发检查由 Agent 完成，不交由用户替代内部验收。
3. 对共享增量验证 `hub_spoke` 四至八节点、`step_row` 二至六阶段、`editorial_columns` 二至六栏及每个人物栏一至四人、无图表格的显式声明。保持其他风格原有默认行为。
4. 饼图和进度数据须进行有效值、非法值、编辑更新和保存重开验证；KPI 条长与百分比使用同一数据源。涉及导出代码时做对应隔离功能验证，不因此把实际样稿导出变成默认交付。
5. 保持 20 种共享构图、48 个 profile 和原 100 条来源记录一致；布局可用于所有有效风格和 speech / reading。新增来源独立记录，不重编号旧来源。
6. 运行相关 Skill 校验、结构与链接检查及与修改相称的代码测试。以正式构建器完成两种用途的计划、配图与构建验证，再按 [接入验证与安装](../../white-blue-slides/references/adding-styles.md#接入验证与安装) 安装；更新已有共享包前备份，不覆盖无关 Skill。上述方向与安装授权已经具备，不重复索取；具体安装完成状态以安装位置验证结果为准。

验证结果记录在项目 `examples/beige-ring-business` 中。未验证的能力不能写为通过；本次没有用户要求的 PDF 或 PPTX 交付，样稿默认交付 HTML。

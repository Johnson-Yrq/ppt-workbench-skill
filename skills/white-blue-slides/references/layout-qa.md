# 基本排版 QA

每份成稿交付前，Agent 都要做一轮基本排版 QA：逐页看实际渲染，判断布局是否合理，发现问题就修改并重建，再交付。这一步属于制作流程，不需要用户要求，也不设批准节点。PPTX／PDF 导出、PowerPoint 实看和播放器功能回归不在这一步里，仍只在用户明确要求时执行（见 [默认交付与职责](export.md#默认交付与职责)）。

## 流程

1. **构建正式稿后运行审查器**，得到逐页截图、总览图和 `report.json`。`<shared>` 为 `white-blue-slides`，审查器需要 Node、Playwright 与本机浏览器：

   ```sh
   node <shared>/scripts/audit_deck.cjs <project>/演示稿.html --out <project>/qa --browser chrome
   ```

   环境缺 Playwright 或浏览器时，改用当前可用的浏览器工具逐页截图，不跳过看图；确实无法渲染时在交付说明中写明未做 QA 及原因。
2. **先修 `report.json` 的问题**：越界、重叠、缺图、外部依赖、图表标签被裁等 `issues` 必须修复；`warnings` 与 `manualReview` 逐条看图判断。
3. **再看图**：先看 `overview.png` 把握全稿节奏，再逐页打开截图，按下方清单检查。`ok: true` 只表示机械诊断通过，不代表布局合理。
4. **修改并重建**：按“先改结构和内容，再调尺寸”的顺序处理（见下文），只重跑审查器并复看改过的页面，直到清单没有明显问题。
5. **交付时简述**：说明看过几页、改了哪些页及原因；仍有取舍或缺素材的页如实写出。不声称做过未执行的检查。

`qa/` 目录是过程文件，与 `deck.json` 一样不算交付物。

## 逐页清单

| 方面 | 看什么 |
|---|---|
| 碰撞与越界 | 标题压到页码、页头或短线；文字、图片、图表互相遮挡；正文或图片压住页脚；内容超出安全区 |
| 重心与留白 | 内容挤在上半页、下半页大片空白；一侧满一侧空；栏目高度差过大；图片过小或被压成细条 |
| 对齐 | 同一行栏目的标题是否对齐；相邻页同类结构（同一系列的场景页）位置是否一致 |
| 层次 | 每页是否有 2–3 级：标题 → 引导句或加粗条目名 → 灰色说明；没有整段平铺、所有文字同字号同颜色 |
| 断行 | 标题在语义处断行，末行不留单个字或标点；能力名、产品名不被折断；窄栏没有逐字折行 |
| 密度 | 演讲型一页一个判断、最多三项要点、留白不少于一半；阅读型段落不超过约三行一段，装不下就拆页 |
| 图片 | 主体完整、裁切合理，与本页内容对应；人物脸部、手部没有被截断 |
| 风格 | 字阶、字重、表面与所选风格包一致；所选风格包的版式经验（如 layout-guide）里标为易乱的结构是否已避开 |

## 修改顺序

1. **换结构**：版式与内容关系不符，或该风格中这种结构易乱时，按 [内容自主选版](layout-selection.md) 与风格包的版式经验换版式或调整栏目顺序、`weight`、`title_column`。
2. **改内容**：长段改写成“要点 + 一句说明”，合并同类、拆页；保持原意、数字与口径，不添加原文没有的事实，改写和合并之处写进 `notes`。
3. **调字段**：`title_size`、手动 `\n` 断行、`eyebrow`、`list`、`numbered`、`emphasis`、图片 `ratio / zoom / offset`。
4. **最后才用 `custom_css`**，且只调内容区。同类问题在多页、多稿反复出现时，应改进主题或共享层，而不是每稿写补丁。

QA 中修改了页序或版式，同步更新 `大纲.md`。

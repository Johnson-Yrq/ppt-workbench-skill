# 先转化为制作大纲

用户给出的原始材料（零散大纲、文档、讲稿、产品手册、会议纪要）不直接写进 `deck.json`。动手选版、生图或构建前，先把内容转化成一份适合所选风格与用途的**制作大纲**，再按大纲逐页制作。用户已给出逐页大纲时也照此整理：补齐关系、版式、配图与口径，原文与页序保持不变。

## 存放与时机

- 写在项目目录 `<project>/大纲.md`，与 `deck.json` 同级；已有制作大纲时沿用并更新，不另起一份。
- 风格与用途确定后再定稿大纲；两者尚缺时可先整理事实与页序，等选择明确后补版式与字数。
- 大纲不是批准关卡：写完即继续制作，回复中简述页数、主线和【待补】项。用户要求先看大纲时，等其确认再动手。
- 制作中调整页序、拆页或换版式时，同步改大纲，保持它与 `deck.json` 一致。

## 结构

开头一张全局设定表：

| 项 | 写什么 |
|---|---|
| 风格 / 用途 | style ID 与 `speech / reading` |
| 页数 | 用户限定的页数，或按内容拆出的页数及理由 |
| 署名与品牌 | 用户提供的单位、Logo；未提供写“不放” |
| 配图 | 生图、用户供图或无图；哪些素材必须由用户提供（真实界面、Logo、真实人物） |
| 事实口径 | 数字与说法的来源，以及不能扩大的表述 |

然后逐页（`## P01｜页面主题`）：

- **结论**：这一页要让听众或读者记住的一句判断，通常就是页标题。
- **关系与数量**：`cover / explanation / parallel / sequence / comparison / hierarchy / statistics / data …` 与条目数，对应 [内容自主选版](layout-selection.md) 的 `layout_intent`。
- **上屏文字**：按用途预算写成最终上屏的短句。演讲型每页一个判断、最多三项要点、条目说明一行；阅读型把机制、比较、来源和边界放在页面上。
- **版式**：首选与备选结构。所选风格包有版式经验（如 [黑白大理石版式选用](../../monochrome-marble-slides/references/layout-guide.md)）时按它选，避开该风格中易乱的结构。
- **配图**：张数、主体、动作、画幅与裁切；纯文字页写“无图”及理由。
- **讲稿**：放不上页面的细节、过渡语和口径边界，后续写进 `notes`。
- **来源 / 待补**：数字与引语注明出处；缺失信息标【待补】，不编造。

文末汇总【待补】清单（演讲人、日期、Logo、真实照片、未提供的页面内容等）。

## 转化要点

- 先定主线和页序，再分配每页的一个结论；一个页面装不下的内容拆页，不靠缩字。
- 上屏文字和讲稿分开写：演讲型压缩上屏、细节进讲稿；不删事实口径。
- 上屏文字按视觉层次写：每页 2–3 级——标题，引导句或加粗的条目名，灰色小字说明；并列内容写成“要点 + 一句说明”，不整段平铺。
- 内容可以为版面改写：原文段落过长、不成结构时，改写成短要点、合并同类或拆页，保持原意、数字与口径，不添加原文没有的事实；改写处在讲稿或来源中注明。
- 标题两行以内，在语义处断行，预估字数是否符合所选风格的标题宽度（例如窄标题栏每行约 6 字）；放不下先精简措辞。
- 原文中的数字、单位、时间区间与限定词（“约”“十余间”“测算值”）原样保留。
- 用户写明的视觉要求逐条带入，制作时写进 `visual.requirements`。

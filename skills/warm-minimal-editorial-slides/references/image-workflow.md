# 配图流程

摄影承担本风格的主要视觉表达。规划时为多数适合配图的内容页安排独立图片：大空间主图讲整体，物件或动作特写讲细节，条带连接阶段，多图对应不同场景或服务。三至五张 contact sheet 中每张各有作用，不重复裁切同一张图来凑数。用户指定的纯文字、无图和固定构图页照办，纯图表页也可保留留白。

先复用用户已提供且合适的真实素材；需要新图时优先使用可直接调用的内置生图工具，按工具规则生成并保存到项目中。没有内置工具时，沿用共享 [生图 API 流程](../../white-blue-slides/references/image-api.md) 或人工供图，继续完成不依赖图片的工作。原始 Canva 照片仅作视觉参考，不复制进成稿。

## 正式项目的图片字段

本风格选用 `editorial` 时以真实摄影为主，这八个变体的共享结构均需配图：`cover / intro / contents / about / process / closing` 使用单个 `image`；`services` 使用 `images` 的 1–3 张图；`portfolio` 使用 `images` 的 2–6 张图。单图与多图字段互斥，不能因允许纯文字构图便省略这些变体的必需图片；明确要求无图时选择支持无图的其他版式或按共享扩展机制实现。每张图独立填写 `src`、`alt`，可选 `caption` 作为可编辑说明，缺图时补齐自己的 `brief`。若选择 `layout: reading`，才按该布局的 composition 使用既有图片数量；阅读型用途不要求选择该布局。其他共享布局各按自己的图片字段，不套用 editorial 数量。

在项目 `deck.json` 中填写项目内素材路径，用共享 `prepare_images.py` 输出逐图提示词和清单。制作缺图时可使用 [演讲示例](../assets/deck.example.json) 或 [阅读示例](../assets/deck.reading.example.json) 的结构，但要改写每页对象、动作、构图与文件名，不能把示例照片的题材当作固定业务模板。

## 每张图的简报

在本包 `assets/image-style.txt` 的风格基底上，补充本页独有内容：

- **对象与动作**：本页到底呈现谁、什么物件、什么空间，以及正在发生的具体动作。
- **语义作用**：图片解释哪一条观点；概念图不冒充客户项目、真实办公室、人员或成果。
- **镜头与材质**：真实尺度、暖调低饱和、自然斜阳或柔光、细微颗粒；根据内容选择石、木、亚麻、陶等材质，不把材料清单机械塞入每张图。
- **画幅与裁切**：主图、竖幅、条带、全景或细节；写清主体位置、必须保留的部分，以及页面文字所在的安静区域。

例如：以亚麻工作台上的材料样本和双手取放动作表达共同选择；以一条连续、自然光照射的木质走道表达阶段推进；以不同场景的真实工作动作组成服务多图。它们是可替换的视觉机制，不是固定题材模板。

只生成照片素材，不生成整页幻灯片。标题、Logo、年份、数字与业务标签由可编辑页面承载；照片不包含文字、水印和虚构业绩。满版短句页用柔焦或自然暗部留出可读区域，不靠大块渐变遮罩补救。

整稿保持光线、色温和颗粒一致，同时改变距离、镜头与具体对象。本包在 `assets/style.json` 指定 `image_background: "scene"`，提示词保留现场的空间、材质与自然光背景，不要求照片背景匹配页面纸色。共享默认值 `paper` 继续用于既有模型风格的纯色纸底；此设置只控制提示词，不修改照片像素。照片使用正常混合，不套用模型风格的纸色映射或底色消除。按照素材本身安排裁切；使用或编辑图片所需的查看属于素材处理，不另设逐张验收。生成文件与必要元数据备妥后继续构建 HTML，按基本排版 QA 逐页看图后交付。

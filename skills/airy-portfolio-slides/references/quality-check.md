# 检查参考与开发验证

普通演示稿完成真实内容、必需配图与可编辑离线 HTML 后交付，由用户自行导出和检查。Agent 不默认开展整稿内容审查、批量截图、逐页验收或导出检查；用户明确要求 PPTX、PDF 或代查时，完成对应产物与验证。构建失败、缺失资源和结构错误仍须修复，详见共享 [默认交付与职责](../../white-blue-slides/references/export.md#默认交付与职责)。

## 用户自行查看时可参考

- 居中封面、纯文字主张和图文页是否形成舒缓节奏，中文是否自然断行，留白是否保留主要内容。
- 近白纸色、黑色衬线字与细线页脚是否统一，页码是否对应真实页序，品牌是否来自当前项目。
- 彩色照片是否保留自然层次，幕后黑白照片是否有叙事理由；作品是否由独立素材组成，裁切是否保住主题。
- 纯作品页是否保留可编辑的语义标题，正文、图注、页码和条目是否可编辑；虚构内容是否明确。
- 阅读稿是否提供独立理解所需的上下文与边界；真实项目、人物、数据和联系信息是否有来源。

## 风格开发与接入

本节用于主题、共享布局与工具开发，不是每份成稿的自动验收流程。用户已于 **2026-10-05** 回复「采用，并安装」，明确批准本方向的中文样稿、正式接入与安装；本包为 **ready / 1.0.0**。历史草稿阶段不限制正常制作，同范围维护不重复索取批准；将来另开独立方向时才按 [新方向批准规则](../../white-blue-slides/references/adding-styles.md#最小清单示例) 提供代表样稿供确认。

1. 以 `style_packs.py --list` 检查本包可作为 ready 风格被发现，核对清单、资源与重复 ID；正式样例使用共享构建器，保留其他风格与无效清单的既有处理。
2. 开发时查看受影响的代表页面：居中封面和主张、右下理念、图文分栏、无标题作品页、不等高拼图及三图收束。检查中文回退、裁切、留白、动态页码和编辑入口；源第 9、10 页印有重复页码，新稿按实际页序生成。
3. 对共享增量验证 `type_poster` 的 statement 与 placement、`editorial_columns.show_title`、单列 gallery 的 `row_weights` 及 `columns.photos` 计数。无标题展示仍须在编辑态可见；图片资源独立嵌入，默认字段保持旧稿行为。
4. 检查受影响能力在其他有效风格及 speech / reading 中可用；保持 20 种共享构图、48 个 profile 和原 100 条来源记录的既有边界。新增来源独立记录，不重编号旧来源。
5. 按改动范围运行 Skill 基础校验及相关代码测试。仅改说明文档时检查结构与链接；修改编辑、保存或导出代码时才补测对应功能，未验证的功能不能写为通过。
6. 更新正式安装时依 [接入验证与安装](../../white-blue-slides/references/adding-styles.md#接入验证与安装) 完成与改动相称的两种用途代表构建、素材清单与视觉验证；安装前备份相关目录，不影响其他 Skill 和用户文件。演示稿的 `--draft` 仅供缺图预排，不能用缺图稿作为成品。

工具、必需素材或事实缺失时，记录具体缺口并继续独立部分，不把未验证功能写为通过。已有批准只覆盖本方向与已授权范围，不扩展到其他新方向。

# PPT 制作工作台

本入口只负责选择与接入；实际制作遵循所选风格的 Skill。风格决定页头、封面尾页、字阶、边距与配图等视觉，类型决定信息密度，主体布局由共享套件提供，三者分开。一个项目记录一种风格，不把不同风格的视觉规范拼在一起。

## 识别风格与类型

`<shared>` 是同级 `white-blue-slides` 目录。先读取现有项目和当前任务已确认的选择，再运行：

```sh
python3 <shared>/scripts/style_packs.py --list
```

此命令自动发现同级风格包，返回可用的 `id / name / description / skill_file`；用实际清单呈现选项，不把清单写死为两种。若某个包报错，保留其他有效选项；用户指定的包不可用时说明具体缺口，不悄悄换风格。共享套件缺失时先检查本项目的 `skills/white-blue-slides`，确实缺失才说明需要安装。

- 优先级：当前用户明确选择 → 当前项目中基于用户反馈记录的选择 → 询问缺少的维度。直接调用某个风格 Skill 已经是风格选择；沿用现有稿也不重新问卷。软件主题本身不等于选择海蓝玻璃风格。
- 尚缺风格或类型时，在拆页、排版和生图前一次问清缺少的项。风格展示清单中的名称和简短特点；类型解释为“现场讲解的演讲型”或“发给读者独立阅读的阅读型”。两项都缺时合并提问，已明确的项不再问。页头、封面尾页与字阶按所选风格自主安排，不由全局入口限定某组预设；用户主动指定时照办。
- 等待期间可读取大纲、整理事实来源与已有素材；无回复、预选项或示例字段不代表选择。用户明确授权“你来选”时按其目标选择并简短说明，无需重复索取选择。
- 在新项目 `deck.json` 根对象显式写入 `style` 与 `presentation_mode: "speech" / "reading"`。旧稿省略字段时仍可兼容原白色风格／演讲型；这种兼容默认不能用于替用户决定新稿。

## 按选择制作

读取清单中所选风格的 `skill_file`，以它作为实际制作流程；加载其视觉与配图规范。共享的数据结构、版式、图表与播放器由该风格引用，不另起问卷或第二套制作流程；交付前按共享 [基本排版 QA](../white-blue-slides/references/layout-qa.md) 逐页看图并修改。

先按共享 [制作大纲](../white-blue-slides/references/outline.md) 把用户内容转化为适合所选风格与用途的 `大纲.md`（逐页结论、关系与数量、上屏文字、版式、配图、讲稿与【待补】），再按大纲动手。

逐页按共享 [内容自主选版](../white-blue-slides/references/layout-selection.md) 判断关系、数量、素材与数据条件，再用 `select_layout.py` 筛选真实可执行的候选。共 48 个执行策略，不把某一批新增构图当作全部布局。常规选版自主完成，不增加批准步骤。

两种类型的规则见 [用途与信息密度](../white-blue-slides/references/presentation-modes.md)：演讲型围绕结论和少量支撑展开；阅读型把机制、依据与边界留在页面，用图表、流程、矩阵、图标和文字增加信息。用途不限定固定配图比例、栏目数量、字号或布局，按内容从共享版式选择。配图承担明确作用，图表有可靠数据才采用 [离线 ECharts](../white-blue-slides/references/charts.md)。

配图取图方式与风格无关：有内置生图工具直接生成；没有时先问用户是否用自己的生图 API（按共享 [image-api](../white-blue-slides/references/image-api.md) 由用户在终端配置，密钥不经过对话），否则人工供图。

有生图能力时，主动为适合的页面生成内容相关的图片，不只在大纲点名“配图”的页面放图。让多数适合配图的内容页有独立场景，按内容采用主图、条带、局部特写或多图；保持所选风格和图片之间的差异。明确要求纯文字、无图或固定构图的页面照办；图表与关键文字仍保持可编辑。

默认交付可编辑、离线单文件 HTML。交付前按共享 [基本排版 QA](../white-blue-slides/references/layout-qa.md) 运行 `audit_deck.cjs`，逐页看截图检查布局是否合理（碰撞、重心与留白、对齐、层次、断行、密度、图片裁切），修改并重建后再交付，交付时简述看过与改过的页。PPTX／PDF 由用户通过播放器自行导出；Agent 不自动导出、不做 PowerPoint 实看或播放／编辑回归。用户明确要求 PPTX、PDF 或更深入的检查时，完成所要求的部分。构建失败、结构错误与缺失资源须修复，见共享 [默认交付与职责](../white-blue-slides/references/export.md#默认交付与职责)。

## 持续新增风格

用户要求新增或迭代风格时，按 [新增独立风格包](../white-blue-slides/references/adding-styles.md) 创建同级包。每个包独立设计页头、封面尾页、字阶、边距、主题与配图；六种页头只属于最早的素白蓝调、海蓝玻璃与写实微缩包，不自动扩展到新风格。新增主体布局进入共享套件供所有风格复用，不绑定某个风格 ID；无需修改本入口的选项或复制共享脚本。已确认的设计方向直接采用，尚未确认的新方向先做样例供用户选择。更新 Skill、验证套件或制作类型对比示例时，不启动真实演示稿的用途问卷。

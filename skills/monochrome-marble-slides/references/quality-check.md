# 检查参考与开发验证

普通演示稿完成内容、必需素材与可编辑离线 HTML 后交付，由用户自行导出和检查；Agent 不默认执行整稿内容审查、批量截图、逐页验收或导出检查。用户明确要求 PPTX、PDF 或代查时，完成相应产物和必要验证。构建失败、结构错误与缺失资源仍须修复，见 [默认交付与职责](../../white-blue-slides/references/export.md#默认交付与职责)。

## 用户自行查看时可参考

- 黑白反转、大衬线字、短横线页码与留白是否一致，中文标题是否出现孤字或被裁切。
- 大理石纹是否克制且不遮挡正文，黑底页的辅助字、线条和图表是否清楚。
- 商务照片是否保留自然色彩、完整人物与可信动作，姓名与职能是否来自真实资料。
- 目录、分组、图表、指标、来源和联系信息是否可编辑，来源与数字口径是否清楚。
- 阅读稿是否保留独立理解所需的背景、机制和边界，示例内容是否始终标明为示意。

## 风格开发与接入

本节是主题和共享组件开发必须完成的 QA，不是每份成稿的自动验收流程。检查与修复由 Agent 执行，不交给用户替代内部验收。本包为 **ready / 1.0.0**；用户于 **2026-10-05** 明确回复「采用，安装，并提交」，批准当前中文样稿方向、正式接入、安装及相关改动提交。同方向维护不重复索取批准；未来独立方向仍按 [新方向批准规则](../../white-blue-slides/references/adding-styles.md#最小清单示例) 提供可审阅样稿并确认。

1. 用 `python3 <shared>/scripts/style_packs.py --list` 检查唯一 ID、清单与资源，本方向应出现在正式可用清单中。开发未来草案可用 `--include-drafts`；演示稿 `--draft` 不得绕过草案的风格状态。
2. 在开发预览中查看十五页代表构图，覆盖五种表面、独立页头、中文标题、照片裁切、大理石边条与底衬。检查文字和图表无重叠、无溢出，深浅表面对比清晰；修复问题后再展示。
3. 验证共享扩展：`side_index` 2–12 项；`editorial_columns` 2–6 栏；`groups` 2–6 项且 title 必填、text/icon 可选；无正文 text 栏必须有 heading 或承载可见页标题。图片、人物和正文的原有行为应保持兼容。
4. 验证嵌套 chart 栏遵循完整图表合同；`shared.editorial_charts` 按真实图表栏数计 2–6 项，不能以类别数、全部栏目数或计划声明代替。图表脚本只在实际有图表时内嵌，图表与图标的计划数量必须匹配实际组件。
5. 图表验证有效值、非法值、数据编辑、HTML 保存重开与离线播放；原生 PPTX 发现器应能处理相同图表节点。涉及导出代码时做相应隔离功能验证，不因此自动导出实际样稿。未运行的能力不记录为通过。
6. 运行 Skill 校验、相对链接与资源检查，以及与改动相称的共享代码测试。保持 **20 种共享构图、48 个 profile** 一致，不限制为本风格专用。
7. 以正式构建器完成 speech / reading 的计划、配图与构建验证，按 [接入验证与安装](../../white-blue-slides/references/adding-styles.md#接入验证与安装) 运行共享 selftest 并安装。更新已有共享包前备份相关目录，检查安装位置的实际可用状态。本次方向、安装及相关改动提交授权已具备，无需重复索取；安装完成状态以实际验证及主任务报告为准。

项目 `examples/monochrome-marble` 保存样稿、素材出处和实际开发验证记录。结果应区分已完成、未验证与发现的问题；本文件给出检查要求，不代替运行结果。当前默认产物为 HTML，后续用户明确要求的导出必须一并完成。
